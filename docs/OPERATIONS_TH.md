# ใช้งานระบบจริง — CCR After Hours 2026

อัปเดต 22 ตุลาคม 2026: เจ้าของขอเปิดใช้งานโหวตและจัดการข้อมูลจริงแล้ว ใช้ฐานข้อมูล Supabase project `vjvptuecwewmqhkedybs` แคมเปญ `ccr-2026` และ `voting_mode=open`

## ผู้ร่วมงาน

1. เปิด `party.html` เลือก RSVP / ของขวัญ / ธีม แล้วกดบันทึก
2. เปิด `vote.html` เลือกอาหารครบ 8 หมวด แล้วกดบันทึก
3. ตรวจข้อความยืนยันจากระบบกลาง พร้อมใบรับและเวลาบันทึก

ไม่ต้องล็อกอินหรือขอรหัสเชิญในรอบเปิด ระบบเก็บรหัสสุ่ม 256 บิตในเบราว์เซอร์เพื่อเชื่อมสองฟอร์มและอัปเดตคำตอบเดิมเมื่อส่งซ้ำ ฝั่งฐานข้อมูลเก็บเฉพาะ hash ของรหัสนี้ การเปลี่ยนเครื่อง เบราว์เซอร์ หรือเคลียร์ site data จะถือเป็นคนละรหัส จึงไม่รับรองหนึ่งคนหนึ่งคะแนนข้ามทุกอุปกรณ์ หากต้องการใช้สิทธิ์เดียวข้ามเครื่อง ให้ผู้จัดออกและแจก invitation code ส่วนตัว

การเลือกอย่างเดียวยังเป็นฉบับร่าง กรณีอินเทอร์เน็ตขัดข้องหรือรอบปิด ระบบไม่ถือว่าส่งสำเร็จ การกดล้างฉบับร่างไม่ลบข้อมูลที่ส่งไว้ในระบบกลาง ติดต่อผู้จัดหากต้องการลบข้อมูลกลาง

## ผู้จัดงาน

ล็อกอินที่ `admin.html` ด้วย Supabase Auth และบัญชีที่อยู่ใน `public.admin_users` หน้าเริ่มต้นแสดงช่องล็อกอิน โหมดตัวอย่างต้องเลือกเปิดเองและไม่เขียนข้อมูลกลาง

หลังล็อกอิน:
- ดูคะแนนจริงและ RSVP ที่อัปเดตทุก 20 วินาทีขณะเปิดหน้า หรือกดรีเฟรช
- ส่วน 07 แก้ไขใบโหวต แก้ไข RSVP ลบคะแนน ลบ RSVP หรือลบทั้งสองส่วนตามรหัสผู้ร่วมงาน
- ตรวจ Audit Log ของคำสั่งแอดมินล่าสุด 100 รายการ
- ส่งออกคำตอบ CSV หรือสำรองคำตอบพร้อมประวัติ JSON เก็บก่อนลบข้อมูลสำคัญ
- เปิด / ปิดรับคำตอบได้ ข้อมูลที่ส่งเมื่อปิดรอบถูกปฏิเสธฝั่งฐานข้อมูล
- จำนวนเป้าหมายเป็นฐานคำนวณอัตรามีส่วนร่วม ไม่ใช่ข้อจำกัดจำนวนคนหรือการยืนยันตัวบุคคล
- สร้างรหัสเชิญและเพิกถอนรหัสได้ รหัสที่ถูกเพิกถอนไม่ถูกนับรวมและส่งใหม่ไม่ได้

คำสั่งแก้ไขและลบบันทึกข้อมูลพร้อม Audit Log ใน transaction เดียว หากขั้นตอนใดล้มเหลวทั้งหมดจะย้อนกลับ ไม่รายงานสำเร็จจาก localStorage

เมื่อลบทั้งคะแนนและ RSVP แถวนั้นจะหายจากตารางคำตอบ ส่วนทะเบียนรหัสผู้ร่วมงานยังอยู่ในตารางรหัสเชิญเพื่อใช้รหัสเดิมอัปเดตภายหลังได้ ใช้ปุ่มเพิ่ม/แก้คำตอบในตารางรหัสเชิญเพื่อเพิ่มคำตอบให้รหัสที่ยังไม่มีข้อมูล หากต้องการหยุดไม่ให้รหัสนั้นส่งใหม่ให้กดเพิกถอนรหัสด้วย

## ปิดรอบและเก็บผล

ปิด Campaign ก่อนตรวจจำนวนคำตอบและคำนวณ Popularity / งบ 2,000 / งบ 2,200 บาท ส่งออกหลักฐานแล้วจึง Freeze เมื่อพร้อมล็อกผล Freeze ป้องกันการแก้ไขข้อมูลและการเปิดใหม่ตามกติกาเดิม

ยืนยันเวลาเริ่มงาน จำนวนโต๊ะ ราคา ปริมาณ และ availability กับร้านอีกครั้งก่อนสั่งจริง ผลโหวตไม่ใช่การอนุมัติสั่งอาหาร

## ตรวจระบบซ้ำ

รัน `npm test` และ `npm run check` เพื่อตรวจโค้ดและแค็ตตาล็อก

`python scripts/cloud-smoke.py` เป็นการทดสอบระบบสดแบบเลือกเรียกเอง ใช้ตัวแปร `CCR_ADMIN_CREDENTIALS_FILE` ชี้ไปยังไฟล์ JSON ส่วนตัวนอก repository ที่มี email/password สคริปต์สร้างคำตอบชั่วคราว ตรวจอ่าน/แก้ไข/ลบ แล้วลบคำตอบทดสอบและเพิกถอนรหัส ไม่พิมพ์รหัสผ่านหรือ JWT ห้ามใส่ไฟล์ credentials ลง Git
